# PaperPilot Pro V4.0

V4.0 turns the extension into a compact literature workbench and replaces duplicated identity and history rules with a shared library module. This release integrates the DOI improvements into the current upstream application, including its citation, notes and settings features.

## What changes in daily use

The popup opens with tools collapsed and activity tucked into a disclosure, leaving search and paper cards visible. Search combines words, quoted phrases and `title:`, `author:`, `journal:`, `doi:`, `year:` or `notes:` fields. Results rank by where terms match; year and title ordering remain available. Thirty records render at a time. Cards expose reading, favorite and DOI actions directly, with secondary actions in **更多**.

Edits, favorites and removals address a stable record identity inside the background queue. A concurrent page visit can no longer move the editor onto another array position. Removal offers eight-second undo while the popup stays open; restoration retains intervening additions. Repeated visits keep notes, known bibliography, favorites and accumulated download/copy actions. Unknown years and dates remain unknown.

Exports now produce files rather than only copying text. Clipboard export remains available. Complete JSON backup always contains the entire library, even when search has no matches. Imports merge atomically, preserve local notes and treat distinct DOI records as separate works. The existing 500-record library limit and favorite protection remain.

Scholar clustering uses DOI and normalized-title indexes instead of pairwise Levenshtein comparisons. Conflicting DOI identities, different known years/authors, and word-order differences are kept separate. Exact shared identifiers or compatible normalized titles can be folded into an accessible source drawer. This conservative rule can leave differently titled preprint/published versions unfolded.

DOI extraction supports encoded resolver URLs, copy artifacts, balanced punctuation, SICI suffixes, prioritized article metadata and relevant JSON-LD. Reference and recommendation regions do not provide fallback article identity. Title lookup examines five candidates per provider and refuses ambiguous identities. Local unresolved metadata expires after five minutes. PDF addresses are shown as candidates until checked during download.

## Validation

- `npm run verify`: static syntax/version/routing checks, 121 unit and service regressions, E2E publisher fixtures and performance budgets.
- Real Chromium MV3 extension run: seven DOI page scenarios; Scholar identity clustering and keyboard source drawer; 67-record library with 30-row rendering; compound search, notes typing, sort/reset, concurrent page addition during editing, removal/undo, complete native JSON backup during empty search, and identity-aware JSON import.
- Existing controls: settings/Overview synchronization, failure rollback, API streaming, cancellation, errors, retries, abstract absence, back navigation, themes and viewport limits.
- Package files are checked against the tested source. Scholarly and AI responses are controlled fixtures; these tests do not establish live coverage of every publisher or DOI registration.

## Compatibility and migration

The major version is a user-requested milestone. There is no intentional configuration or public-message API removal. Record IDs, page URLs and action arrays are additive; existing records normalize when read or changed. JSON backup remains `paperpilot.history` schema version 1. Existing preferences are retained, with compact tools as the default when no collapse preference exists.

Install the updated files into the same extension installation to retain data, reload the extension, then refresh Scholar/publisher tabs. Unpacked-extension IDs depend on the installation path; using a different directory may produce a separate library. Export a complete JSON backup when transferring between installations.

The earliest declared Chrome version was not separately retested; validation used current Chromium. DOI recognition targets common academic prefixes with 4–9 registrant digits. ShortDOI aliases, scanned-image OCR and closed Shadow DOM are not resolved locally. Clear-all still requires confirmation; per-record undo is available only during its popup session.
